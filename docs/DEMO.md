# 演示讲稿

配套脚本：`scripts/demo.py`。四个场景各对应一个创新点，顺序刻意递进：
**只读 → 被拦 → 修复 → 回滚**，从"最安全"走到"最需要机制保障"。

```bash
python scripts/demo.py --list     # 开场前先过一遍场景与观察点
python scripts/demo.py            # 全部跑（真实调用模型，约几分钟）
python scripts/demo.py --only 3   # 时间紧时只演示修复循环
```

演示工作区是临时目录里的一个小项目：`calc.py` + `test_calc.py`，
其中 `average` 有两个 bug（空列表崩、没做四舍五入）。

---

## 开场（30 秒）

> 这是一个终端原生的编程智能体。核心设计只有一条：**模型不碰操作系统**。
> 它只能输出结构化调用，由宿主校验后在 WSL2 沙箱里执行。
> 下面四个场景分别对应四项机制。

演示时**把终端字号调大**，重点让观众看清工具行的等级标签与验证/修复提示。

---

## 场景 1 · 只读分析（对应"双工具架构"）

```bash
agent run -C <演示工作区> "calc.py 里的 average 函数有什么问题？只做分析，不要改任何文件。"
```

**讲解点：** 看工具行 —— `→ [L0 只读] shell_exec: ...`。这个等级是**宿主判定的**，
不是模型自报的。模型即便说自己"只读"，只要命令里有 `rm` 一样会被拦。

工具不是 shell 的同义词：找文件用 `find_files`、搜内容用 `search_code`，
它们返回结构化的「文件:行号:内容」，模型不用自己在一堆输出里找。

**预期：** 模型指出两个 bug，并主动说"文件未改动"。

---

## 场景 2 · 命令分级（对应"可审计的命令安全策略"）

```bash
agent run -C <演示工作区> "用 pip 装一个 requests 库。"      # 不加 -y
```

**讲解点：** 命令**不会直接执行**，图会挂起并停下来问你。

```
需要确认 (L2 变更性)
  pip install requests
  理由：安装依赖
  执行？ [y/N]
```

这里可以现场敲 `n` 演示拒绝，再跑一遍敲 `y`。

> 如果现场不方便交互，用 `--yes` 跑，它只把"人工确认"降级为"自动批准"，
> **等级判定不变**，审计里记为 `approved` 而不是 `denied`。

**追一句：** 判定完全在宿主侧，白名单 + 危险正则 + 复合命令取最高级，
**无法解析的一律降级为 L2**，不赌。

---

## 场景 3 · 失败驱动的修复循环（对应"失败驱动的命令修复循环"）

```bash
AGENT_VERIFY_COMMAND="python3 -m unittest discover" \
  agent run --write --yes -C <演示工作区> \
  "修好 average：空列表返回 0.0；非空时结果保留两位小数。改完确保测试全绿。"
```

**讲解点：** 改完文件后**自动**跑验证 —— 不需要模型主动要求，而且不打扰用户
（跑的是宿主从项目清单推导出的固定命令，模型影响不了跑什么）。

失败时不是把一大坨 stdout 丢给模型，而是先结构化：

```
验证失败 FAILED (failures=1)
  · test_calc.py:14 self.assertEqual(average([]), 0.0)
  · ZeroDivisionError: division by zero
↻ 第 1/3 次修复 FAILED (failures=1)
```

**重试上限是硬性的**（默认 3 次，按步计算）。到上限后模型被明确要求停止再试、
指出问题所在与需要的授权 —— 而不是无限烧 token。

> 想现场演示"修不好"的路径：把 `AGENT_MAX_REPAIR_ROUNDS=1` 并给一个不可能通过的
> 验证命令，就能看到它如实上报而不是假装成功。

## 场景 4 · 回滚（对应"可回滚的修改流程"）

```bash
agent run --write --yes -C <演示工作区> "把 calc.py 里的 add 改成返回 a - b。"
agent snapshots      # 看快照（时间戳命名，天然按时间排序）
agent diff           # 最近一次改了什么
agent undo           # 一键回滚
cat calc.py          # 确认已还原
```

**讲解点：** 每次改动前自动留底到 `.agent/backups/<快照id>/`。

**关键一句**：回滚**本身**也可回滚 —— 恢复前会先把当前内容也留一份。
所以一次误回滚不会把你当下的改动抹掉，再 `undo` 一次就滚回来。

---

## 收尾（30 秒）

> 四条主线合起来是同一个判断：**自动化能力可以给，但每一次落地的动作
> 都要能被看见、被拦住、被撤销。**

- 模型只输出意图，命令由宿主在沙箱里执行
- 危险命令过不去，判定不依赖模型自报
- 失败会被结构化捕获并驱动修复，修不好就如实上报
- 每次改动都可回滚，回滚本身也可回滚

**可选补充**：`agent audit` 展示审计表 —— 每一次工具调用、每一次审批结果、
每一次验证、每一次回滚都在里面。

## 备选：TUI 演示

如果评委更想看交互，用 `agent tui`：

- 左侧计划面板随步进打勾，右侧是工具时间线
- 侧栏常驻显示**当前权限等级**（L0 只读 / L1 可写）
- L2 命令弹 `ModalScreen`，`y` 批准 / `n` 或 `Esc` 拒绝（默认动作是拒绝）
- `/undo` `/diff` `/sessions` `/memory` `/audit` 都在界面里

## 备选：Web 演示

`agent web` 打开 `http://127.0.0.1:8765`。流式对话、多会话列表、API 联通状态。

**注意**：Web 端**固定拒绝**变更类命令（没有做审批交互），
所以它只适合演示只读分析与多会话，不适合演示改动。要演示改动请用 TUI 或 CLI。

## 常见现场问题

| 现象 | 处理 |
|---|---|
| 第一次命令很慢 | WSL 发行版冷启动，先跑一次 `agent doctor` 预热 |
| 模型话太多 | 这是模型风格，不影响机制演示；直接往下讲 |
| 网络抖动导致调用失败 | 显示了 `运行失败` 与原因，重跑即可 —— 失败本身也是可观测的一部分 |
| 想跳过某场景 | `--only N` |
| 演示完想保留工作区 | `--keep` |
