# 事故复盘索引

复盘是最好的"反例教材"：AI 最容易重复别人已经踩过的坑，所以这里的内容必须**可被检索**，
不能埋在日期命名的一次性报告里。

| 日期 | 标题 | Severity | Status |
|---|---|---|---|
| [2026-10-21](2026-10-21-orchestrated-write.md) | 并发写编排的两个 P0：worktree 脏检查误判 + 待合并 implement 被重启 | P0 | 已修复 |

## 写复盘的要求

1. **时间线 / 根因 / 防御缺口 / 行动项**四段，缺一不可；
2. 根因要写到**结构性教训**（"只看 git 退出码就是在赌"），
   不要停在"某个函数写错了"——后者只对那一个 bug 有用；
3. 行动项要带**回归测试名**，否则无法证明它不会再来一次；
4. 结尾写「给 Agent 的提醒」，把教训变成可执行的检查清单，并回流到 `AGENTS.md`。
