# ADR-0008：长期记忆只做显式增删，不做 LLM 自动提炼

- **Status**：accepted
- **Date**：2026-10-22
- **Owner**：项目作者
- **Tags**：记忆 · 可审计性优先

## Context

主流做法是让模型在会话结束时自动蒸馏出几条"值得记住的项目约定"。
它的吸引力很明显：不用人管，越用越聪明。

但在一个**主打可审计**的系统里，这个交换不划算：

1. 自动记忆容易积累噪声——模型会把一次性的临时决定当成永久约定；
2. 难以回答"这条结论是哪来的"——没有来源、没有时间、无法证伪；
3. 一旦记错，错误会以"系统记得的事实"的形式被反复引用，比单次错误更顽固。

## Decision

宿主**不做后台自动蒸馏**。记忆只有两个来源：

- 人：`agent memory --add "…"`（或 TUI `/remember`）；
- 模型在运行中**显式调用** `memory_search` 检索、`memory_save` 写一条具体事实
  （`--write` 会话可用）。

每条记忆仍是一次明确的、可见的工具调用，逐条入审计。

## Consequences

### 好的

- 每条记忆可追溯（来源 / 时间 / 过期信息在 `memory.meta.json`）；
- 写入前扫描密钥，避免把凭据固化进长期记忆；
- 高度相似的新旧事实保留最新版本，不会无限膨胀。

### 坏的 / 代价

- **需要人主动维护**：忘了记就真的没有；
- 记忆质量取决于写的人，没有自动兜底。

### 中性 / 需要留意

- 检索侧仍是智能的：每次运行按与请求的相关度取 top-K（`AGENT_MEMORY_TOP_K`，默认 8）
  注入系统提示，模型也可按需 `memory_search`。
  **规避的是"写入自动化"，不是"检索智能化"。**
- `untrusted` profile 下不读取仓库 `.agent/memory.md`，记忆移到仓库外——
  因为仓库内容不可信，见 `THREAT_MODEL.md §5.9`。

## 复核

- **Verified by**：`pytest -m "not llm" tests/unit/test_memory.py tests/integration/test_longterm_memory.py`
- **Revisit when**：出现记忆质量下降证据或自动提炼需求时

若出现"记忆质量随使用下降"的实际证据，先加的是**过期与冲突治理**，
不是自动提炼。
