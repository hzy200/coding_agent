# ADR-0001：模型只输出意图，宿主代执行

- **Status**：accepted · 事后补录
- **Date**：2026-10-22
- **Owner**：项目作者
- **Tags**：安全 · 架构

## Context

需求是"让模型驱动一个能改代码的智能体"。最省事的做法是给模型一个 shell 句柄，
让它自己决定跑什么。但那样：

1. 命令风险由模型自评，而模型会犯错、也会被读到的文件内容诱导；
2. 改动无法结构化（改了什么、能不能撤，全靠猜）；
3. 没有任何可信的记录能回答"它到底做了什么"。

可选的中间方案是"模型输出命令文本 + 宿主做正则过滤"。否决：词法守卫是
best-effort、可绕过（编码、变量、间接执行、新变体无穷），见
`THREAT_MODEL.md §5.5`——它可以减少确认噪音，但不能当安全边界。

## Decision

LLM **拿不到任何操作系统句柄**，只产出结构化调用 `{tool, args}`；
宿主用 `tools/` 下的 `BaseTool` 实现全部能力，校验后在 WSL2 沙箱里执行。

由此推出四件事：

- 命令分级在 `sandbox/policy.py`，**不看模型自报**；
- 文件修改走专用工具（精确替换 + diff + 写前备份），**不经 shell**；
- L2/L3 先挂起等审批；
- 审计由 `runtime` 写，前端绕不过。

## Consequences

### 好的

- 危险操作在宿主侧被拦，判定不依赖模型的诚实；
- 每次改动都有 diff 与快照，可回滚；回滚本身也可回滚；
- 一切都可追溯，审计是宿主写的，任何界面都绕不过；
- 前端（CLI/TUI/Web）只需消费领域事件，加前端不动编排。

### 坏的 / 代价

- **能力扩展必须写代码**：想加一个新能力要写 builder + 注册 + 登记等级 + 补测试，
  不能靠改一句 prompt 解决；
- 未登记的工具按 L3 处理，漏登记会让工具永远要确认 —— 这是故意的摩擦；
- 工具返回的是结构化产物，模型看不到原始 stdout，某些需要人工看输出的操作会受限。

### 中性 / 需要留意

- 经 shell 的修改**不产生快照、不发 `FileChanged`**（shell 输出无法结构化解析）。
  这是本决策的直接代价，已在 `ACCEPTANCE.md` 作为已知限制列出。

## 复核

- **Verified by**：`pytest -m "not llm" tests/unit/test_architecture.py tests/unit/test_approve.py`
- **Revisit when**：需要模型直接持有长期进程句柄，或新增工具协议时

若出现"模型需要直接持有长期运行进程的句柄"这类需求（如交互式 REPL 调试），
本决策需要重新审视——那会要求一个新的、带独立隔离与审计的通道，而不是放开 shell。
