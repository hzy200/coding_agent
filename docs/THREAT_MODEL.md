# 威胁模型

> 面向实现：说清**保护什么、假设对手是谁、现在挡得住什么、要挡住更强的对手还差什么**。
> 结论一句话：**默认交付是"防误操作"（T1），不是"防主动越狱"（T2）**；T2 需要额外一层内核级约束。

## 1. 资产（要保护什么）

| 资产 | 在哪 | 为什么值得保护 |
|---|---|---|
| 工作区外的用户文件 | WSL `$HOME`（`~/.ssh`、`~/.aws`、shell 历史…） | 私钥/凭据泄漏 |
| 宿主 Windows 文件 | `/mnt/c`、`/mnt/d` | 整台机器的数据 |
| 宿主进程环境 | 宿主的 `DEEPSEEK_API_KEY` 等 | 凭据泄漏、API 额度 |
| 工作区里的项目 | WSL 工作区 | 被误改/删 |
| 审计与快照 | 宿主 `.agent/audit`；工作区 `.agent/backups` | 可追溯性与可回滚 |

**已核实（2026-10-04）**：

- 宿主进程的 `DEEPSEEK_API_KEY` **不会**进入 WSL 登录 shell（`wsl.exe … bash -lc 'echo $DEEPSEEK_API_KEY'` → 空）。
- **审计与 checkpoint 落在宿主侧**（`<宿主 cwd>/.agent/`），不是 WSL 工作区 —— 沙箱内命令改不到。
- **快照 `.agent/backups` 在工作区内**（WSL），因此工作区可写时，agent 能改动/删除自己的留底。

## 2. 信任边界与攻击面

```
模型（不可信输出）
   │  {tool, args}            ← 唯一入口，宿主解析
   ▼
宿主策略（policy / approve / tools）  ← 判定权在这里，模型自报不算数
   │  经 stdin 传给 WSL
   ▼
WSL2 登录 bash → （可选）bwrap 挂载命名空间 → 命令
   │
   ▼
Linux 用户空间（非 root）
```

攻击面：shell 命令、文件工具路径、git/deps 参数、审批交互、前端 SSE/HTML、checkpoint/审计文件。

## 3. 两个威胁模型

### T1　防误操作（**默认交付目标**）

假设：模型**善意但会犯错**，或被**普通**（非对抗）提示误导；不主动设计逃逸。

这是默认配置（`AGENT_SHELL_SANDBOX=off`）的定位：把"手滑、越界、危险命令"挡住或交人工确认。

### T2　防主动越狱（**对抗性，当前不满足**）

假设：模型输出（含被读取的文件内容）**主动尝试**越过工作区、读取凭据、外传数据。

**当前不满足 T2**，因为它要求"命令无论怎么拼都出不去"，而我们默认只有词法守卫 + 进程边界。

## 4. 现有防线分级

| 防线 | 实现 | 归属 |
|---|---|---|
| 命令四级分级 + 复合取最高 | `sandbox/policy.py` | T1 |
| 危险模式拦截（`rm -rf`、`sh -c` 包装、管道执行等） | `policy.DANGER_PATTERNS` | T1（**已知模式的枚举**，非完备） |
| 未知命令/解析失败 fail-closed 为需确认 | `policy` | T1 |
| 只读命令**参数越界升级**（`~`、外部绝对路径、`..`、`$()`/变量） | `policy._escalate_auto_command` | T1（词法 best-effort） |
| 引号感知（字面量不误判，`$()`/`sh -c` 照扫） | `policy._mask_quoted` | T1 |
| `.agent` 在 shell/git 路径的防护 | `policy`（整树 `git add`、`.agent` 引用 → L2） | T1 |
| 路径双重校验（词法 + realpath，含悬空链接） | `pathguard` + `fs` | **接近 T2**（对文件工具路径是硬约束） |
| 审批在节点、执行在 `tools` 唯一咽喉 | `graph/nodes/{approve,tools}.py` | **接近 T2**（前端绕不过） |
| 资源上限（CPU/文件/进程，沙箱内 `ulimit`+`timeout`） | `sandbox/limits.py` | T1 |
| 审计（宿主侧、追加写、失败显式报出） | `audit/` | **接近 T2**（沙箱改不到） |
| 可选内核级隔离 `AGENT_SHELL_SANDBOX=bwrap` | `sandbox/wsl_exec.py` | **T2 的一层**（opt-in，默认 off） |
| 前端只消费事件、HTML 用 `textContent` | `tui/` `web/` | 接近 T2（无 XSS、无旁路执行） |

## 5. 从 T1 升到 T2 需要的前置条件

按"防线层"给出：现状 → 缺口 → 达标要做什么。

### 5.1 文件系统隔离（最关键）

- **现状**：默认 off，命令以用户身份运行，`/home` 可读；opt-in `bwrap` 已能隐藏 `/home` `/root` `/mnt`。
- **缺口**：默认不隔离；bwrap 依赖非特权 user namespace（多数 WSL 可用，但不保证）。
- **达标**：
  1. 默认改为 `bwrap`（或提供"无 bwrap 即拒绝启动"的部署档）；
  2. 只读根 + **白名单** bind（只挂工作区与必需系统目录），而非现在的固定集合；
  3. 明确"工作区是唯一可写点"。

### 5.2 网络隔离

- **现状**：**未** `--unshare-net`，隔离视图里仍能 `curl`。
- **缺口**：数据外传通道敞开。
- **达标**：`bwrap --unshare-net` + 受控代理白名单（否则 `deps_install`/构建不可用，需权衡）。
  这是"安全 vs 可用"的直接取舍，必须显式配置而非默认放开。

### 5.3 进程与能力

- **现状**：`--unshare-pid --unshare-user`；未 drop capabilities。
- **达标**：`--cap-drop ALL`、`--new-session`，并限制可执行集合（现在只读 `/usr` 仍可运行任意系统程序）。

### 5.4 内核对接口（seccomp）

- **现状**：无 syscall 过滤。
- **达标**：`bwrap --seccomp` 加载策略，限制危险 syscall（如 `ptrace`、`mount`、原始 socket）。

### 5.5 命令解析

- **现状**：**词法守卫是 best-effort、可绕过**（编码、变量、间接执行、新变体无穷）。
- **结论**：**T2 不能把它当兜底** —— 必须由 5.1 的 OS 隔离兜底；词法守卫只作为"减少确认噪音 + 拦截明显危险"的 T1 手段。

### 5.6 资源隔离

- **现状**：`ulimit`；对子进程/新会话的约束不完全。
- **达标**：cgroup v2（memory/cpu/pids 硬上限），不依赖进程自我约束。

### 5.7 审计完整性

- **现状**：审计在**宿主侧**（好），但快照在**工作区内**（可被 agent 改）。
- **达标**：快照也移出工作区或加校验和；审计考虑远端/只追加存储，防"改完再抹痕"。

### 5.8 凭据

- **现状**：`DEEPSEEK_API_KEY` 不在沙箱（已核实）。
- **达标（T2）**：仍要把"宿主 env 默认不继承"固化为测试（防止哪天加了 `WSLENV` 把密钥带进去）。

### 5.9 提示注入（真正的 T2 主战场）

- **现状**：读到的文件内容与用户指令**同等信任**，都进模型上下文。
- **达标**：内容信任分级（工具结果标记为"数据、非指令"）、对"由文件内容触发的危险动作"强制人工确认。这是模型层问题，隔离层解决不了。

### 5.10 审批与前端

- **现状**：策略在宿主、前端绕不过（好）；但 `--yes`/`approve` 模式会全放行；Web SSE 无鉴权（默认绑 `127.0.0.1`）。
- **达标**：T2 场景禁用 `approve` 模式；Web 加鉴权并禁止非本地绑定。

## 6. 结论

- **默认交付 = T1**：足够支撑"防误操作 + 可审计 + 可回滚"的毕设叙事，且已在文档中如实声明。
- **T2 的最小可行组合**：**默认开启 bwrap（含 5.1–5.4）+ `--unshare-net` + 快照出工作区 + 内容信任分级**。
  这是一条独立的工作线，不应宣称在默认配置下已具备。
- **答辩建议**：把 T1/T2 的边界讲清楚——"我们做的是 T1，并给出了通向 T2 的路径与代价"，
  比含糊地说"很安全"更站得住。

## 7. 维护

本文档随防线变动更新。新增/修改安全相关代码时，对照 [ARCHITECTURE.md](ARCHITECTURE.md) 第 6 节不变量表与本表
确认：**属于 T1 的手段不要被当成 T2 的保证**。
