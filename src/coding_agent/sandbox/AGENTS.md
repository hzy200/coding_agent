# sandbox/ · 执行安全层

**整个系统里唯一"模型意图落地成副作用"的地方，改动风险最高。**
威胁模型与防线分级见 `docs/THREAT_MODEL.md`，改这里之前必须对照第 4 节。

## 一条原则

> 宿主内置工具，模型只输出意图。LLM 拿不到操作系统句柄，
> 只产出 `{tool, args}`，由宿主校验后在 WSL2 沙箱里执行。

判定权**永远在宿主**——命令分级看命令文本，不看模型自报的"我是只读"。

## 禁区

- `policy.py` 的分级表与 `DANGER_PATTERNS`：改它就是改安全边界。
  新增白名单词前先想清楚它能不能被用来拼出危险命令。
- 无法解析的一律降级为 L2（`_classify` 的兜底）。**不要改成"解析失败就放行"**。
- `cp` / `ln` / `mv` 刻意**不**自动放行：它们能绕过文件工具的精确替换、diff 与写前备份。
- 路径校验是**双重**的：词法归一化（`pathguard`）+ 沙箱内 `realpath`（`fs`），
  含悬空符号链接。任一层都不要删。
- `AGENT_SHELL_SANDBOX=bwrap` 配了却不可用时**拒绝执行**，不静默降级。
- 每条命令以 `env -i` 启动；`printenv` / `env` 归为 L3，`approve` 模式也必须人工确认。

## 重要认知：词法守卫不是安全边界

`policy` 的引号感知与参数越界升级是 **best-effort、可绕过**（编码、变量、
间接执行、新变体无穷）。它的作用是"减少确认噪音 + 拦明显危险"，
**T2（防主动越狱）必须由 OS 隔离（`bwrap`）兜底**。
不要在评审里把词法守卫当成完备保证。

## 快照

- 写前留底到 `.agent/backups/<快照id>/`；**回滚本身也可回滚**（恢复前先留当前内容）。
- 经 shell 的修改**不产生快照**（shell 输出无法结构化解析），这是已知限制，不是 bug。
- 快照在工作区内，因此工作区可写时 agent 能改自己的留底——这是威胁模型里
  明确的残余风险（T2 达标项：快照移出工作区或加校验和）。
